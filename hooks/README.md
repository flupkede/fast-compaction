# fast-compaction Claude Code mod

This plugin uses Claude Code function hooks to replace a compaction with the
original messages, minus the tool calls and tool results Jev judged no longer
needed. `hooks/fast-compaction.ts` is a thin adapter: it reads the plugin options,
finds the TypeSafe key, hands `session.compact` transcripts to the
`fast-compaction` library in `src/` (the plugin folder is the repository
root, so the hook imports it directly) and maps the result back onto session
messages. User and assistant text is never touched. Jev is sent the whole
conversation as `state` (tool outputs replaced by a one-line note) and, for
every tool call outside the pinned first and newest messages, two questions:
whether the call should stay and whether its full output should stay. An
item is kept when Jev's probability reaches `keepThreshold`; a dropped result
is truncated to its first `truncateHeadChars` characters plus a one-line note,
and a dropped call disappears with its result.

The state is fitted into `maxStateTokens` in stages: tool inputs are
truncated, then long texts are abridged (oldest first, pinned messages last),
then old messages collapse to a `[… N chars omitted …]` note, then old tool
calls shrink to one line each, then old call-less messages are left out and
runs of old call-only messages fold together. Questions are split into as many requests as
needed so each request (state plus questions) stays under `maxRequestTokens`;
the full state is resent with every request. Token counts are estimated
without a tokenizer, calibrated to land a little above what Jev reports.

The mod is an early-access Claude Code function-hook module. The checked-in
type reference was generated by Claude Code **2.1.274**. Enable the function
hooks surface before installing or loading it:

```sh
export CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1
export TYPESAFE_API_KEY="<your TypeSafe key>"

claude plugin marketplace add tamaratran/fast-jev-compaction
claude plugin install fast-compaction@fast-compaction
```

For local development:

```sh
CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1 claude --plugin-dir .
```

## Configuration

The plugin declares these `userConfig` values in
`.claude-plugin/plugin.json`:

| Option | Default |
| --- | ---: |
| `asker` | `cloud` |
| `keepThreshold` | `0.5` |
| `preserveRecentMessages` | `6` |
| `preserveStartMessages` | `2` |
| `compactAtPercent` | `60` |
| `minReductionRatio` | `0.25` |
| `targetFloorStartPercent` | `50` |
| `targetFloorMinPercent` | `25` |
| `targetFloorStepPercent` | `5` |
| `maxStateTokens` | `25000` |
| `maxRequestTokens` | `30000` |
| `truncateHeadChars` | `300` |
| `model` | `jev-latest` |
| `ollamaUrl` | `http://localhost:11434/v1/systemone` |
| `jevTimeoutMs` | `8000` |

`asker` picks the judge: `cloud` (default) asks the TypeSafe Jev API and needs
the `apiKey`; `ollama` posts to the local Ollama System One endpoint
(`ollamaUrl`) with model `clef-flash` and a 10-minute timeout — local
inference is slow — unless explicit options override.

The TypeSafe key can be supplied as the sensitive `apiKey` plugin option or
through `TYPESAFE_API_KEY`. The environment variable is the recommended
development setup.

Every option except `apiKey`, `asker`, `compactAtPercent`, `minReductionRatio`,
`targetFloorStartPercent`, `targetFloorMinPercent`,
`targetFloorStepPercent`, `jevTimeoutMs`, `model` and `ollamaUrl` is passed
straight to
the library; see the root
README for what they do. When the session reports its context window, the
hook also gives the compaction a token target of
`window × floorPercent / 100`: the floor starts at `targetFloorStartPercent`,
steps down `targetFloorStepPercent` after every accepted Jev compaction down
to `targetFloorMinPercent`, and resets to the start after any fallback to the
built-in summary. Without a usage reading (subagents, or `$.session.usage()`
failing) the compaction runs threshold-only. The `session.compact` hook runs the Jev requests
concurrently and stops waiting after `jevTimeoutMs`, inside the engine's hook
budget. If Jev fails or times out,
the response is malformed, the key is unavailable, the history cannot be
fitted into the state budget, or the estimated reduction is below
`minReductionRatio`, the hook logs a fallback and delegates to Claude Code's
built-in compaction. The outcome is shown as a toast and logged with the
reduction, per-reason counts, state size and request count; a per-call
`decisions:` line with both probabilities is logged for diagnosis. The
`turn.complete` hook lets the turn finish first, then, when `context.percent`
reached `compactAtPercent`, requests compaction in the background (retrying
while a new turn is running), with an in-flight guard.

## Training data

The hook cannot collect training data: the plugin sandbox forbids `fs` access
(both static and dynamic `import()` of `node:*`), so the old `trainingLog` /
`trainingDir` hook options are gone. The library-level callback
(`trainingLog: (record) => ...`) and `createTrainingLogger` remain available
to scripts outside the sandbox — `npm run replay` uses them to write
`compactions-YYYY-MM.jsonl` from stored session transcripts.

## Stats

`/compaction-stats` prints token and savings totals over every session,
`/compaction-stats session` the current one, `/compaction-stats reset` clears
them. The
ledger lives in the plugin's `$.store`, one key per session (the 200 most
recently active are kept), written from `turn.complete` (main and subagent
token usage, Claude Code's cost) and `session.compact` (Jev or fallback,
reduction, duration). Against a shim-backed local judge it also shows where
the time goes per compaction: model load + prefill + generation, averaged
over the Jev compactions that reported it.

`/compress` queues fast-compaction for right after the current turn — the host
refuses a nested compaction inside a command hook, so the `turn.complete` hook
runs it past the percent threshold.

`Saved` credits each Jev drop (context before times character reduction) once
per later main-loop API call until the next compaction, calls per turn
estimated as the turn's summed input over the last response's input, then
prices it at the main loop's cache-read share (reads 0.1x, the rest full
price). It is an estimate against keeping the pre-compaction context.

## Scope and caveat

Function hooks are early access and may change between Claude Code releases.
This mod uses the generated declarations from 2.1.274 in
`types/claude-code.d.ts`; regenerate and review that file after a
Claude Code upgrade.
